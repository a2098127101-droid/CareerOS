# CareerOS v1.0-beta0 · Runtime Certification Candidate

## Release intent

beta0 changes the release criterion from "integration code exists" to "the target deployment can produce verifiable runtime evidence". No external dependency is marked PASS solely because a URL or key is configured.

## New runtime gate

The full certification profile verifies:

1. live PostgreSQL connection, schema health and repository certification;
2. live pgvector extension and vector column;
3. Redis connectivity;
4. shared distributed rate-limit state across two independent Redis clients;
5. Redis queue/state/worker round-trip;
6. S3-compatible private object put/get/presign/delete round-trip;
7. real semantic embedding call without `local_hash` fallback;
8. real LLM provider connectivity.

The resulting certificate is HMAC-signed, bound to the non-secret deployment coordinates and expires after `RUNTIME_CERTIFICATION_MAX_AGE_HOURS`.

## Production readiness change

For non-demo production, `/ready` and the admin readiness report now reject a missing, stale, tampered, environment-mismatched or incomplete runtime certificate.

## Worker architecture

`run_worker.py` no longer imports `app.main`. The worker independently constructs Settings, RepositoryContainer, EmbeddingGateway and the background-job runtime, then registers shared handlers from `app/job_handlers.py`. This removes FastAPI/web initialization side effects from worker startup.

## Staging harness

`deploy/docker-compose.staging.yml` provisions the intended certification topology:

- PostgreSQL 16 + pgvector;
- Redis;
- MinIO private object storage;
- API;
- independent worker;
- one-shot certifier profile.

The packaged environment does **not** contain valid production secrets or real model API credentials. Those must be supplied by the deployer.

## Truthfulness boundary

The current build environment used to prepare this release does not expose Docker, a live PostgreSQL server, Redis, MinIO, a real semantic embedding credential or a real generation-model credential. Therefore those live checks remain `NOT VERIFIED` in this release package until the staging gate is executed on provisioned infrastructure.
