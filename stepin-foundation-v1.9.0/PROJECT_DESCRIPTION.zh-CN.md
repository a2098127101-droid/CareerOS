# StepIn 项目介绍

## 一句话介绍

StepIn 是一个面向零基础、零实习经验学生的实践能力培养系统。它不从课程、专业标签或岗位测评开始，而是让学生先完成一件真实、简单、可以马上动手的小任务，在反复实践、修改和换场景练习中逐渐形成能够独立完成、能够迁移、最终能够清楚表达的实践能力。

## 为什么做 StepIn

很多学生并不是“没有学过东西”，而是不知道真实工作每天到底在做什么，也不知道自己是否适合某类工作、应该从哪里开始。传统路径往往要求学生先选方向、学课程、找项目、投实习，但对于完全没有实践经验的人，这些选择本身就是门槛。

StepIn 把起点往前移：先做一件足够简单、但来自真实工作逻辑的任务。学生先接触工作，再逐渐理解知识、方法、专业和岗位。课程与知识不是产品本身，而是在实践需要时出现的支持内容。

## 核心路径

StepIn 的学习路径不是“课程 → 考试 → 证书”，而是：

**开始做 → 跟着做 → 自己做 → 根据反馈修改 → 换一个场景再做 → 小任务组成项目 → 多次任务叠加成能力 → 把做过的事情讲清楚。**

前期不急着做职业匹配。学生先完成跨专业通用的小任务，例如找关键信息、整理材料、比较判断、发现问题、说明理由、完成交付和根据反馈修改。完成基础实践后，再体验数据、文字、人物、问题判断等不同材料，职业方向在真实表现基础上逐渐出现，而不是由一份前置问卷直接决定。

## StepIn Foundation

Foundation 是面向零经验学生的公共实践底座，目前围绕十项基础实践能力组织：

- 看懂任务
- 找出关键信息
- 整理信息
- 比较与判断
- 发现问题
- 说明理由
- 清楚交付
- 根据反馈修改
- 换场景再做
- 把做过的事情讲出来

系统记录学生完成任务时用了多少提示、是否能够独立完成、换一个场景后是否仍然能够完成，以及多次不同任务是否共同证明了同一种能力。

## 从小任务到真实项目

StepIn 不把“项目”当作学生必须先理解的概念。学生先完成几个独立的小任务，再由系统把这些任务连接成一个小项目。例如：看材料 → 分类 → 找出问题 → 排优先级 → 写出建议。学生是在做完以后才发现，自己已经完成了一次完整的工作过程。

后续专业工作台包括表格整理、候选人筛选、客户线索判断、访谈整理、问题处理、资料研究和需求排序等。它们不是课程页面，而是接近真实工作的操作环境。

## 能力不是自评，而是做出来的

StepIn 把每一次真实操作记录成 Evidence，并将修改过程、换场景表现、作品版本和教师反馈连接起来。一个能力不会因为“做过一次”就被认定掌握，而是通过不同任务中的重复表现逐步增强可信度。

最终，学生不仅拥有一组完成记录，还能够回答：

- 我真正做过什么？
- 我现在能独立完成什么？
- 哪些事情换一个场景也能做？
- 我有哪些可以展示的作品？
- 我怎样把这些经历写进简历、在面试中讲清楚？

## 产品原则

StepIn 不以“多学课程”作为核心目标，也不鼓励简单堆叠模拟项目和实习标签。专业、课程、知识、AI 和职业推荐都只是帮助学生完成实践过程的工具。

产品真正要培养的是：学生面对一件陌生但可理解的事情时，能够知道从哪里开始，能够一步一步做完，能够根据反馈修改，能够在新情境中再次完成，并最终把自己的实践过程和能力表达出来。

## 当前开发状态

当前 StepIn Foundation v1.9.0 已实现公共实践能力模型、基础任务 Runtime、渐退式提示、跨任务能力聚合、小任务组合项目、实践表达、延迟职业分化，以及与现有 Practice / Evidence / Artifact / Teacher Review 体系的衔接。

当前 GitHub `main` 同时包含 CareerOS production v1.5 的 Domain Intelligence、RLS、安全、生产部署和 CI 能力，因此 v1.9 Foundation 正通过独立集成分支逐步移植，避免用旧基线覆盖现有生产化代码。

## 目标用户

主要面向：

- 没有实习经历的大学生；
- 不知道真实岗位每天具体做什么的学生；
- 不知道自己适合什么方向、也不知道从哪里开始的学生；
- 学过课程但无法把知识转化成实际工作能力的学生；
- 需要形成可验证项目、作品、简历和面试表达材料的学生。

StepIn 的目标不是让学生“看起来有经历”，而是让他们真正从不会做，走到会做、能独立做、能换场景做，并且能把自己做过的事情讲清楚。
