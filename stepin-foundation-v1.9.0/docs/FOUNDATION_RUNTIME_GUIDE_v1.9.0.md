# StepIn v1.9.0 · 公共实践底座

## 1. 这一层解决什么

v1.9 不再把“选岗位、选项目、选课程”作为零基础学生的第一步。新用户先做一组任何专业都能理解的小工作动作：看懂任务、抓重点、整理信息、比较判断、发现问题、说明理由、交代结果、根据意见修改、换场景再做、把做过的事讲清楚。

专业知识、课程和岗位 Workbench 继续保留，但下沉到公共实践之后。

## 2. 十项公共实践能力

- 看懂要做什么
- 找出关键信息
- 把信息理清楚
- 比较后作判断
- 发现明显问题
- 把理由说清楚
- 把结果交代清楚
- 根据意见再改一次
- 换个场景还能做
- 把自己做过的讲出来

能力不是通过一次问卷判定，而是从任务结果、提示使用、独立完成和换场景结果中逐步形成记录。

## 3. 第一组八个基础任务

1. 4 件事，先做哪一件
2. 6 条话里，只留下最重要的 3 条
3. 把 6 条消息分清楚
4. 找出这张小表里最明显的问题
5. 把这件事交代给下一位同学
6. 别人说不清楚，再改一版
7. 换件事，再自己判断一次
8. 把前面几步连起来做一次

第 8 步会将前面的动作组合成第一份小项目，并继续写入原有 Artifact/Evidence 体系。

## 4. 帮助逐步减少

Foundation Runtime 使用受控脚手架：

`guided → assisted → independent → revision → transfer → combined`

前两步最多提供 2 条提示，中段最多 1 条提示；换场景和组合项目阶段不提供直接提示。系统记录每个任务用了几次提示，因此“会做”不只看最后答案，也看是否越来越少依赖帮助。

## 5. 小任务如何变成项目

Foundation 不是八道孤立题。第 8 步由 `project_chain.py` 把前面任务中的关键信息、判断、交接和修改动作组合成第一份 `foundation_project` Artifact。后续专业 Practice 仍使用同一 Canonical Artifact/Evidence 版本链。

## 6. 做完以后怎么表达

基础小项目完成后，学生需要先用自己的话复盘。`expression_service.py` 只基于学生实际完成内容生成三种出口：

- 自己看的复盘
- 简历里的简短写法
- 面试时 60–90 秒的说法

表达完成前不会直接开放完整职业路径。

## 7. 专业方向为什么延后

基础任务和表达完成后，学生先经历 3 次不同材料类型的小练习。目前桥接材料来自：表格数据、访谈材料、优先级判断。系统只记录“信息、判断、表达哪类事情目前更顺手”，不把它包装成职业测评。

只有完成这 3 次探索后，完整职业路径才逐渐出现。

## 8. 后端强制规则

已登录普通学生不能通过直接调用 `/api/practice/v1/runs` 绕过 Foundation：

- 基础任务/表达未完成：HTTP 423 `foundation_locked`
- 基础完成但 3 次探索未完成：只能启动受控桥接练习；其他模板返回 `exploration_locked`
- 教师/管理员可为支持和旧流程连续性创建 Run
- 历史上已经存在的进行中专业 Run 不会被 Foundation 强行打断

Foundation 与 Practice 均可显式绑定 `session_id`，防止同一用户未来存在多个 Workspace Session 时把新 Evidence/Artifact 写到错误 Session。

## 9. 教师看到什么

教师工作台新增“基础成长”入口，不必等学生进入人工评审队列。教师可以直接看：

- 已完成几步
- 当前做到哪一步
- 每项公共能力目前到“跟着做 / 自己做 / 换场景做 / 组合做”的哪一级
- 最近每一步用了几次提示
- 最近任务完成度

这不是职业适配评分，而是做事过程的成长记录。

## 10. 与 v1.8 的关系

v1.8 的 Desktop Workbench、Spreadsheet、ATS、CRM、Interview Coding、Issue Tracker、离线 FastAPI + SQLite、附件、真实文件导出、备份、Practice Studio、Windows Portable/Installer 构建链全部保留。v1.9 在这些能力前面新增 Foundation Runtime，并不重写原有 Runtime。

## 11. 当前边界

- 第一组 Foundation Task 目前仍为内置受控内容，还没有无代码 Foundation Task Studio。
- `FoundationAbility` 已形成运行时模型，但跨大量专业任务的能力聚合仍采用保守规则，不等同于正式测评学量表。
- 3 次桥接探索只用于延迟专业分化，不输出“你适合某岗位”的结论。
- Windows 最终 EXE/Installer 仍必须在 Windows x64 构建机完成真实构建和断网 E2E。
